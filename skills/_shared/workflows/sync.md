# Incremental synchronization

Read [the common contract](../mcp-contract.md) before using tools.

list_properties, list_property_placements, list_property_observations, list_account_observations, list_placement_templates and list_property_remediation_costs support their REST offset/sync modes: pageSize 1–100 (default 25), offset pageIndex 0–9007199254740991. The other ten modes are list_persons, list_companies, get_property_roles, list_account_inspections, list_property_inspections, list_property_documents, list_account_reports, list_property_reports, list_inspection_tools and list_certificates. These lists use pageSize 1–100/default 25 and offset pageIndex 0–1000000, except get_property_roles: offset takes no paging fields and returns a complete set/version; sync accepts pageSize only with changedSince, retains roles catalogue and never provides an actionable complete-set version. Offset-only tools also use their own REST bounds: pageSize 1–100; pageIndex 0–9007199254740991 for assigned properties, observation photos/completions/history and 0–1000000 for inspection checklists/report PDF generations. Follow each actual schema; role offset has no paging fields. Result byte limits may require a smaller page (template lists have a 2 MiB limit; ordinary lists 512 KiB); refusal returns no partial page. Never silently truncate.

For a new sync use changedSince=initial; for later changes use the last completed syncCheckpoint. Keep the original changedSince, target/propertyId and includeDeleted choice while passing each returned nextCursor. Only the final page has syncCheckpoint; a cursor is continuation, not a finished checkpoint. A run captures an upper bound: later writes belong to the next run. Offset pageIndex/content filters cannot accompany changedSince; account-observation sync alone retains optional propertyId scope. Treat tokens as opaque and do not construct, edit, reuse across workspaces/collections or expose them to evidence text. Each mode also needs its REST deployment slice. Reads do not require write consent or owner/global write enablement.

includeDeleted returns only currently authorized minimal tombstones, never recoverable content or support restore authority. Remove those record IDs from the local working set without inventing deleted values. A changed permission can narrow visibility; no token promises historical access. invalid_request includes public errors[] with query field and invalid/resync_required. On resync_required, explain that a new changedSince=initial run is needed; do not silently discard saved progress. Keep the same 10 pages/250 rows workflow ceiling for sync and offset together: choose pageSize no greater than the remaining row allowance. Stop with an explicit partial result and preserve the last nextCursor plus original run inputs for an explicitly requested continuation. Never advance the durable checkpoint on an incomplete run.

All 16 sync modes follow the exact REST collection/parent bounds and current visibility. Contact search/company/sort, inspection status, document type/search, report/equipment search and certificate view/search are offset-only. Sync never broadens protected contact, collaborator, equipment or certificate-holder visibility, exposes file content or enables writes. A prior read-only or file-opt-out consent can sync metadata with its existing scopes; do not request a reconnect for sync alone.
